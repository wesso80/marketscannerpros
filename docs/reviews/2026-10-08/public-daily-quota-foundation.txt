Existing behaviour
lib/entitlements.ts defines Free 10 / paid 50 AI questions. Public AI routes perform independent count-then-generate checks using ai_usage. app/api/ai/copilot/route.ts permits access if that check fails. These checks are not an atomic shared reservation system. Their date handling is not the newly specified authoritative Eastern quota day.
lib/proTraderAccess.ts contains legacy paid-tier, operator and promotional bypass handling. lib/auth.ts includes subscription checks for trial identities. These shared helpers are unchanged.
app/api/payments/checkout/route.ts uses configured Stripe price IDs. Its referral branch checks price trial settings, but that is not evidence that the approved seven-day trial, reminder and cancellation lifecycle is implemented. No Stripe calls were made; actual configured prices/trials were not inspected or changed.

Implemented
lib/publicPlans.ts defines the new visitor/Free/Pro limits separately: Symbol 1/3/unlimited; AI 0/5/100. Canonical instrument keys include asset type.
migrations/126_public_daily_quotas.sql adds daily subject buckets and per-resource reservation entries, without modifying existing tables.
lib/publicDailyQuota.ts serializes each subject/day/quota kind with a database row lock, counts pending plus completed work, deduplicates completed reports and pending retries, and rejects mismatched fingerprints. Reservation tokens fence stale workers. Confirmed failures can release credits; uncertain/interrupted work remains reserved until reconciled. Storage failures throw rather than grant access.
Quota day and next reset come from PostgreSQL's clock and America/New_York rules. Response includes reset ISO instant for localization by the UI. Midnight rollover creates a separate day bucket.
