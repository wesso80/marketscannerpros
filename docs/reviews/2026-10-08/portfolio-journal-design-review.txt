Portfolio and Journal: redesign compatibility review
8 October 2026 | codex/public-research-design | staged, not deployed

Scope
Reviewed active workspace routes, PortfolioContent and overview presentation, Journal page/layout, record classification, account/plan helpers and portfolio sync rules. This is a targeted compatibility review, not a complete audit of every API or statistical model. No production/provider calls, account migrations or saved-record changes.

Implemented
app/tools/workspace/page.tsx: flag-enabled Portfolio and Journal become distinct destinations within the shared shell, without the duplicate Track tab bar. Only the active body mounts. Existing panels, callbacks, account gate and auxiliary tools remain. Contextual links join Symbol, Portfolio and Journal; explanatory guidance distinguishes observation, expectation and outcome.
components/portfolio/PortfolioOverview.tsx: opt-in palette/spacing treatment for existing allocation and values. No valuation, allocation or P&L formula changes.
components/journal/layout/JournalLayout.tsx: scoped embedded-page styling and replacement of the old risk-scoring/AI-summary upgrade claim with historical-review wording. Review modules and access gates remain unchanged.

Existing protections found
lib/journal/researchRecords.ts and components/journal/JournalPage.tsx: automated/paper entries remain separate from personal performance; revealing research does not add it to personal KPIs. Existing layout tests cover this.
lib/portfolio/clientSync.ts: server revision, successfully loaded baseline and explicit changed payload are required before syncing. Failed load/conflict blocks sync. Quote refresh is display-only. This work does not change those rules.
Journal prefill retains assetClass/tradeType through journalLinkAsset; existing trade drawers and add/update/close actions are reused. User-entered simulation records are not represented as a linked brokerage portfolio.
PortfolioOverview retains the distinction between open P&L and today's change, plus missing-quote notes. Daily return is not invented.

Unresolved product gaps / implementation backlog
P1 Entitlements: lib/useUserTier.ts getPortfolioLimit currently gives Free 3 positions; lib/free/limits.ts sets FREE_JOURNAL_LIMIT=5. The proposed Free product says one portfolio and basic journal without these exact limits. Decide intended limits, enforce consistently server/client, then update pricing. Acceptance: Free/Pro/legacy/admin matrix tested; downgrade preserves records; limits cannot be bypassed by direct requests.
P1 Copilot: Portfolio and Journal still publish legacy context. New paid evidence-bound Copilot has no verified page adapter here. Do not claim it can explain these pages yet. Acceptance: account-bound allowlisted record evidence, dates/units, no research-paper contamination of personal metrics, 20/day shared allowance and no actions.
P1 Legacy Portfolio public risk displays: app/tools/portfolio/page.tsx still includes derived risk labels, concentration-based correlation proxy and operator-state writes. They were not reclassified or removed in this styling pass. Acceptance: factual exposure/valuation facts labelled with basis; any proxy explained explicitly; internal/admin helpers unchanged.
P1 Record parity: complete a fake-database end-to-end pass covering add/edit/close, duplicate submission, conflicts and downgrade. The browser harness includes opening/closing the Journal drawer, but that added interaction has not yet completed verification; no saves were submitted.
P2 Visual completion: detailed Risk/Allocation/Ledger views and Journal drawer internals still retain some legacy presentation. Apply the shared typography and layout after evidence semantics are agreed; test long symbols, options units, shorts and missing marks.
P2 Research links: test equity, crypto and option-contract prefill end-to-end, including return navigation. Existing helpers were preserved, not comprehensively re-audited.

Source-reading tests follow the moved file. No model changes.
