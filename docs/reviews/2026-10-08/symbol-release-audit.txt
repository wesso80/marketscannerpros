RELEASE BLOCKERS / BACKLOG

P0 — Guest data permission remains unresolved.
app/api/quote/route.ts:31 and app/api/bars/route.ts:19 explicitly describe an authenticated-user requirement as an AV licensing constraint; app/api/intraday/route.ts:56 also authenticates. The new guest core report and comparison backend can fetch equity data despite these existing comments. Those comments are evidence of an existing design constraint, not proof of current contract terms. Do not enable guest provider-backed equity access until the actual permitted redistribution/access model is established. Do not simply remove quote/bars guards.
Acceptance: documented provider permission for each anonymous surface, or a clearly labelled permissible demo/delayed alternative; guest flows make only allowed requests. Keep the approved signed-in three-report Free journey separate from this unresolved guest entitlement.

P1 — The full core report is still partly locked for Free.
app/tools/golden-egg/page.tsx:785 wraps the large evidence/detail section in UpgradeGate(requiredTier=pro,currentTier=tier). The new report quota grants successful Free core reports but does not change that tier. Confirmed paid overlay in all eight visitor/Free page cases (two assets, two widths).
Acceptance: a successfully unlocked core report has no paid overlay over included evidence. Pro-only options/history remains separately gated. No frontend-only bypass; unauthorized direct requests remain denied.

P1 — Specialist gates disagree with the core report allowance.
• app/api/dve/route.ts:54-59: session + paid gate; response still includes the legacy reading payload. Snapshot required for basic volatility should be projected from the shared public evidence, with separately gated premium depth.
• app/api/crypto/breakdown/route.ts:8-13: session + paid gate and optional coin ID; no shared report-unlock check. Preserve canonical crypto identity binding when adding public access.
• app/api/research/news/route.ts:14-27: session + paid gate; no shared report-unlock check or explicit success-response Cache-Control. It declares force-dynamic, but that is not evidence of all cache layers being user-isolated.
• app/api/company-overview/route.ts:18-22 and app/api/ownership/route.ts:16-20: session + paid gates. Ownership uses private,max-age=300 at line 32. Determine which fields are core and which are premium before changing access.
Acceptance: Free's included report sections work for the same canonical unlocked instrument; tab/timeframe changes do not charge another report. A different instrument cannot reuse the unlock. Distinct Pro depth paths keep server-side checks; admin behaviour remains unchanged.

P1 — The new chart has not been integrated into the Chart tab.
app/tools/golden-egg/page.tsx:80 imports the old IntradayCharts page. Its Chart tab makes /api/intraday requests; options GEX can also be requested (app/tools/intraday-charts/page.tsx:728,746). The comparison/indicator UI is in PR #493 and was added to its AI summary component. This branch contains its backend only.
Acceptance: one intended Chart tab exposes Compare and Price & indicators, shares symbol/period correctly, and works through an existing report unlock. Verify assembled #493/#496 code rather than claiming separately passing components prove an integrated flow. Preserve evidence-before-explanation and avoid duplicate chart controls in multiple tabs.

P1 — Public response boundary remains incomplete.
app/api/regime/route.ts:114,180 includes permission; signed-in responses include operatorContext (line 183). No-store is an existing protection; it does not make those fields evidence-only.
app/api/options-scan/route.ts:56 calls checkOptionsAccess, an existing paid/admin gate. lib/options/access.ts uses current effective tier with legacy/promo handling. This is not a new public evidence projection. Keep full chains/history Pro but remove public score/verdict exposure as part of Claude's W3 work, without altering internal models.
Public AI question handlers still return decision/confidence/ACL metadata. The new quota wrapper controls allowance and replay, not content safety or the evidence-only contract.
Acceptance: route-by-route public allow-list contracts, nested-field tests and no private/admin fields in either responses or model prompts. Distinguish account data from public market observations.

P1 — Empty AI responses can consume a credit.
lib/publicAiQuota.ts:41-43 checks error/success/ok flags but does not validate a substantive answer. For example, analyst-context maps absent generated sections to null yet returns HTTP 200. Code finding, not a reproduced live provider failure.
Acceptance: validate each caller's usable answer shape before completion. Empty/malformed outputs must be shown as unavailable without spending a successful-answer credit; retain conservative handling for genuinely unknown provider outcomes. Add fixtures for all-null analyst sections, empty copilot content and malformed explanation fields.

P2 — Page request order and quota feedback need work.
app/tools/golden-egg/page.tsx:386-390 starts Golden Egg, DVE, quote and regime independently. CryptoBreakdown may mount while the core report is still loading because the display condition checks isAuthBlocked, not a completed unlock. Exhausted/error users can still open report tabs; new summary backend rejects the missing unlock, but old specialist routes use their own policies.
app/tools/golden-egg/page.tsx:657 presents a generic feed failure/Retry for quota exhaustion, while the usage counter shows zero. The message should distinguish a daily limit from provider failure and offer prior reports, local reset and signup/upgrade as appropriate.
Acceptance: gate expensive report-specific requests on successful identity-matched admission; retain any deliberately free Overview measurements under their own documented policy. No repeated blocked refresh loops. Display correct reset and retry advice.

P2 — Mobile detail layout and remaining browser scope.
Six successful mobile evidence cases report inner tiles outside the viewport. Review those grids/containers directly; document-wide overflow checks alone are insufficient. Fundamentals and Chart failure rendering were exercised, but a fully populated successful specialist fixture and integrated dual-mode chart still need review.
Acceptance: readable evidence at 390px without clipped data or forced sideways document scroll; keyboard access to all tabs/controls. Then test real Next middleware, reverse proxy Origin/HTTPS handling, cookies across reload/multiple tabs, midnight rollover, symbol switching, expiry changes, logout/downgrade and production-shaped cache headers with fake providers.
