Public plan readiness: Portfolio, Journal, pricing and sign-up
8 October 2026 | codex/public-research-design, reviewed from c58b5815
Read-only code review; no billing, provider, production data or admin changes.

Conclusion
The agreed product policy and existing enforcement are not yet aligned. Do not treat a redesigned pricing page as completion of the entitlement migration. Visual rollout and public daily quotas are separate flags; neither production setting was inspected here.

Agreed policy versus code
1. Symbol: visitor 1, Free 3 distinct canonical instruments per Eastern day; Pro unlimited. lib/publicPlans.ts defines 1/3/unlimited; lib/publicQuotaAccess.ts gates the new policy behind PUBLIC_DAILY_QUOTAS_ENABLED. lib/publicDailyQuota.ts uses America/New_York and a resource ledger. Existing code is not evidence the flag or database migration is enabled in production. Acceptance: repeated opens/refreshes/tabs do not spend another report; simultaneous requests cannot exceed allowance; reset works through DST and displays in local time.
2. Copilot: paid only, 20 questions/day; Free 0. lib/publicPlans.ts and lib/publicAiQuota.ts implement that policy when enabled, with verified subscription lookup and shared quota. Legacy getAILimit in lib/useUserTier.ts still returns different limits. app/pricing/page.tsx currently derives Free AI copy from that legacy helper. Acceptance: pricing, quota indicator and every public AI endpoint agree; admin bypass remains unchanged; no unverified Portfolio/Journal page-context capability advertised.
3. Portfolio: target is one Free portfolio. lib/useUserTier.ts additionally limits Free UI to three positions. app/api/portfolio/route.ts POST and lib/portfolio/serverSync.ts do not contain a matching tier/position-cap check in the inspected save path. This is a code finding, not a demonstrated production exploit. A portfolio count and a position count are different entitlements. Acceptance: decide position policy explicitly, enforce on server and client without blocking close/edit of existing records or deleting records on downgrade. Use fake storage tests, including direct save requests.
4. Journal: target is a basic Free journal. Actual FREE_JOURNAL_LIMIT=5 means FIVE OPEN ENTRIES, not five lifetime entries. app/api/journal/add-trade/route.ts counts is_open=true under an advisory transaction lock before insert. app/api/journal/route.ts POST checks the incoming open-entry count. lib/free/journalQuota.ts rejects counts above five. Acceptance: consistent semantics across add, import/sync and reopen paths; no bypass via partial payloads; closed history preserved; concurrent fifth/sixth insertion tested. This review did not establish all those properties.
5. Macro/M2: target Free summaries and Pro history. Existing Macro public view limits Free observations; the Global M2 page remains under IntelligenceGate's paid access. Do not promise Free M2 access yet. Acceptance: server response projection and page access match, and history never leaks through Free payloads.
6. Paid price: lib/planPrices.ts defines US$24.99/month and US$249/year. app/api/payments/checkout/route.ts selects configured Stripe price IDs. External Stripe prices were not read or changed. Acceptance: isolated Stripe test checkout verifies amount, currency, interval and tax presentation against the published page.
7. Trial: target seven days, card upfront, reminder two days before ending, easy cancellation and record retention. Checkout uses subscription mode/card but does not explicitly set subscription_data.trial_period_days. Its price trial lookup is for referral-coupon handling, not proof of trial activation. No reminder implementation was found in the inspected payments/webhooks paths. Existing pricing describes a seven-day money-back guarantee, which is a different promise. Acceptance: Stripe test mode verifies trial dates, first charge date, one reminder despite webhook retries, cancellation without charge during trial, downgrade with all records retained. External billing configuration remains unverified.
8. Sign-up: app/auth/page.tsx reuses an email magic-link flow via app/api/auth/magic-link/route.ts. This review sent no emails. Acceptance: signed-out sign-up, expired/reused links, safe return URL, Free landing and paid checkout return tested using mocked mail and test billing. Copy should make the free account path explicit.

Prioritised handoff
P0 Before pricing rollout: reconcile the independent design/quota flags; verify migrations and deployed access policy in an approved non-production environment. Remove Free AI and retired Deep Analysis/Golden Egg product promises from the new pricing presentation. Do not advertise the proposed trial until its billing flow passes.
P1 Portfolio/Journal: agree whether existing three-position/five-open-entry limits remain, then enforce consistently without modifying shared admin rules. Preserve all existing records. Test direct requests, imports, reopen/close and downgrade.
P1 Free M2/current options access: finish server projections and access checks before including them in Free benefits.
P1 Sign-up/pricing/account presentation: reuse existing authentication and checkout handlers within the shared design, with truthful supported benefits and legal/support links. Verify mobile and desktop, keyboard focus and error states using fixtures only.
P2 Record-specific Copilot adapters and legacy risk/proxy cleanup: follow portfolio-journal-design-review.txt; styling alone does not complete the evidence-first migration.
