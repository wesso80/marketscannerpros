Public Journal follow-up � supersedes the three implementation gaps above
The public /api/journal/analyze path now shares the paid Copilot ledger through
withPublicAiQuota (journal/analyze). Verified subscription lookup precedes
record/model work. It uses the existing 20/day limit and Eastern reset,
reservation/replay, definite-failure release and interrupted-outcome retention.
Rollout flag PUBLIC_DAILY_QUOTAS_ENABLED remains required; disabled public
access fails closed rather than reverting to the old route. Signed admin and
operator access keeps the previous handler in lib/ai/legacyJournalAnalysis.ts.
No changes to its calculations, access policy or AI prompt in this follow-up.

Evidence is read using a parameterized workspace-owned journal_entries SELECT.
Browser-supplied records are ignored. Only status, outcome, P&L and dates are
read; free-text notes/strategy/emotions never reach the public model. A maximum
of the latest 2,000 records is summarized, explicitly disclosed when truncated.
Closed positive/negative/zero/missing counts are disjoint; inconsistent labels
are disclosed. Open records do not count as closed results. Dates and missing
dates are explicit. We deliberately omit monetary totals/profit factor because
currency and costs are not verified; we do not invent strategy/emotion metrics.
These are saved user records, not broker-verified outcomes.

The model can return only evidence IDs and reviewed explanation keys. Server
validation rejects invented IDs, arbitrary prose and extra fields. The server
renders all sample facts and limitations, so the model cannot hide missing data
or author recommendations. This is a deliberately constrained educational
summary, not an unrestricted conversational Journal analyst. No new model API
or SDK is introduced; it uses the existing public Copilot model configuration.
