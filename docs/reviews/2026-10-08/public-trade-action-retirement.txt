Finding
Removing tools from the educational Copilot did not remove direct /api/ai/actions access. Its POST still accepted generate_trade_plan and risk_position_size, and GET returned stored action parameters/results. Confirmation and idempotency protections were present but did not retire those public capabilities.

Implemented
app/api/ai/actions/route.ts now refuses those two public tools with 403 PUBLIC_TRADE_ACTION_RETIRED and private, no-store headers. The POST check is before parameter validation, action lookup, cache/replay, simulation, pending proposal, confirmation claim or execution. It applies regardless of PUBLIC_DAILY_QUOTAS_ENABLED, so disabling rollout cannot reopen the capability. Body/header claims and paid tier alone do not grant private access.
GET still scopes its database lookup to the caller's workspace, but withholds stored results for the two retired tools from public callers, including pending, confirmed and executed records. Neither parameters nor stored result payloads are returned on refusal. No pending action is cancelled/deleted and no historical result is rewritten.
Signed admin/operator identity checks preserve the existing executor and lookup paths. The original paid-session gate remains. No executor math, shared tool definitions, internal models, admin route or notification/worker code changed. Alerts, watchlists, Journal actions and their confirmation/idempotency paths remain unchanged.

29 tests pass: 11 public retirement cases and the 18 existing ACT boundary cases. New tests cover dry runs, normal calls, confirmations, old response references, forged body/header claims, Free/Pro/legacy paid, rollout on/off, signed out, private dry runs, the actual private sizing calculation and stored-result lookup by ID/idempotency key. Database operations are faked; public retired POST requests perform no database call. Existing ACT tests exercise concurrent confirmation and interrupted/failed outcomes using their fake database.
Type checking reports the same six baseline Stripe API-version/timer errors, with no new errors. No live PostgreSQL, real model, provider, notification or browser execution was used for this backend change. Full suite not rerun.
